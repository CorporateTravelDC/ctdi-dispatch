## Deployment-model framing added

The platform began as a **single-operator deployment** and was made ready for multiple human and agent accounts. An agent running **as the operator's own account** is a designed fallback from that origin, an **exception** whose safety rests on the operator's operational hygiene. The recommended rollout is a confined, organizationally managed agent account, or the agent gateway. Personal-account agents are not allowed as an organizational policy in a larger deployment.

This framing was written into `docs/AGENT_TRUST_MODEL.md` §0, `SECURITY.md` and `docs/COMPLIANCE_SECURITY.md`.

## What deliberately stays as it is

- **Operator-account processes:** the agent GPG key, session grants, database writes and the board key. This is the designed exception, documented in §0 of the trust model, with managed agent accounts as the organizational rollout.
- **Reader sign-in resume:** needs a console session, not a signature. This is the reader plane, distinct from the agent gateway, whose reopening does need a signature.
- **Mutable governance tables:** they stay ordinary state. The chain covers the **event record**. An anchor outside the database (journaled heads now, signed checkpoints planned) is what catches a writer who recomputes the whole chain.
