# CTDI Dispatch — Codebase Reference Draft (2026-09-03)

**Status:** DRAFT, written from a fresh read of the code as it stands on 2026-09-03.
This document describes what the code actually does today — not what any earlier
doc claims about it. It is intended as the source-of-truth input for reconciling
the repo's living docs (README.md, docs/INFRA_MAP.md, docs/COMPLIANCE_SECURITY.md,
etc.). Where something was inferred rather than directly confirmed by reading
code, that is said explicitly. File paths are relative to the repo root
(`/opt/corporatetraveldc/private/ctdi-dispatch-internal`) unless noted.

Scale at time of writing: ~61,100 lines of Python across 163 files under `src/`,
plus ~75 quadlet container units, ~63 host-level systemd user timers, ~90 shell/
Python operational scripts, and a React PWA frontend under `src/runner/frontend/`.

## 1. System overview

CTDI ("Corporate Travel Dispatch Intelligence") is a self-hosted, single-box
aviation/ground-transport dispatch-intelligence platform run on a Raspberry Pi 5
for [operator LLC], LLC — a boutique DC-metro executive services firm
(executive chauffeur transport, executive protection, brand strategy, IT
security). Everything runs locally: rootless Podman containers under systemd
user quadlets, one shared SQLite database, a local llama.cpp inference stack,
a Nextcloud-backed knowledge vault, and ntfy/Pushover for operator alerting.
The standing operator directive, enforced in many places in the code, is
"everything is meant to be local": no third-party position/identity APIs, no
cloud LLM calls (`ANTHROPIC_FALLBACK_ENABLED=false` on this box), and no
secrets in the repo.

What the platform actually does, as read from the code:

- **Real-time FAA SWIM ingest** (`src/ingest/`): six Solace PubSub+ feeds
  (FDPS flight data, STDDS surface/terminal surveillance, TFMS traffic
  management, TBFM arrival metering, ITWS terminal weather, AIM/FNS NOTAMs),
  plus NWWS-OI weather wire over XMPP, local ADS-B/ACARS from the box's own
  SDR receivers, and Amtrak. Parsed into ~75 SQLite tables.
- **REST polling with push/pull failover** (`src/poller/fetchers/`): METAR,
  TFR, NAS status, NWS, NOTAM-REST, MWAA FIDS, ATCSCC ops plan, FAA/OpenSky
  aircraft registries, Eurocontrol, and more — each fetcher automatically
  defers to its SWIM "push twin" when that feed's heartbeat is healthy.
- **Dispatch decision support**: a deterministic CPS ("Critical Predictability
  State") GO/MARGINAL/NO-GO scorer mapped to Part 135.609 HEMS minimums
  (`src/poller/skills/cps_recompute.py`), TFR enrichment, route/flight/train
  impact narratives, and a flight/train/vessel/drone watchlist with a full
  OOOI (Out/Off/On/In) phase state machine fed by ACARS, SMES, TFMS, TBFM,
  ADS-B, and FIDS with an explicit source-authority ordering.
- **LLM-synthesized briefs and watches** (~45 "skills" in
  `src/poller/skills/`): hourly ops and EP-advance briefs, a family of daily/
  weekly themed watches (AAM, aviation, gig economy, concierge travel,
  executive protection, trains/yachts), OSINT monitoring, and digests — all
  generated by a local llama.cpp stack (phi3:mini-class models) with
  deterministic fallbacks.
- **Executive-protection / OSINT intelligence**: RSS-scope scoring
  (`osint_monitor.py`), cross-link entity tracking with auto-promotion
  (`src/common/entity_tracking.py`), EP advance briefs and venue matrices.
- **A second brain** (`src/second_brain/`): a Nextcloud/WebDAV PARA-structured
  markdown vault with a SQLite full-text index, a CUI/PII scrub gate on every
  ingestion path, a deterministic semantic layer (SKOS-style ontology compiled
  into queryable tables), and a wikilink knowledge graph.
- **A public-facing surface** that is physically separated from live data: a
  demo playback API over a scrubbed, promoted archive (`src/demo/`), and a
  static blog mirror of "The Executive Standard" Substack
  (`src/executive_standard/`).
- **Operator interfaces**: a FastAPI web API (`src/web/`, port 8000, tiered
  token auth), a React PWA ("dispatch-runner", `src/runner/`, port 8001,
  tailnet-gated) with map/TFR/brief/trains/signals/intel views and an
  interactive "Dispatch Drawer" chat, and ntfy push topics with per-topic
  deep links back into the runner.

Audience: the operator (a single human dispatcher) plus AI agent sessions
(Claude/Cowork) that work in the repo under explicit governance conventions
(signed manifests, SR-1/SR-2, scrub gates — see §10).

## 2. Container / service map

All images are built from `Containerfile.*` at the repo root by
`build-images.sh` (base `python:3.13-slim`; runner adds a `node:20-alpine`
frontend build stage). Every image bakes in `src/`, `scripts/verify-manifest.sh`,
`scripts/verified-exec.sh`, `security/trusted-signing-key.pub.asc`, and the
signed `MANIFEST.sha256(.asc)` — see §10 on the integrity convention. Units are
rootless Podman quadlets under `.config/containers/systemd/` (the live copies)
with reference copies/extras in `systemd/`. Long-running services are plain
containers; skills are `Type=oneshot` containers fired by host-level systemd
user timers (`~/.config/systemd/user/corporatetraveldc-*.timer`). Production
containers run in a dedicated `production.slice` with explicit `Memory=` +
`--memory-swap=` caps (equal values → clean OOM-kill, no swap thrash) and
`MemoryLow=` protection.

**web** (`Containerfile.web` → `uvicorn web.main:app`, port 8000, published on
127.0.0.1 and the tailnet IP 100.x.x.x). The FastAPI API described in §6.
Reads/writes the shared SQLite DB (`/var/lib/corporatetraveldc/corporatetraveldc.db`);
writes admin triggers as JSON files into `/run/corporatetraveldc/triggers` for
the poller to consume; serves SSE at `/api/v1/events`. Always-on.

**poller** (`Containerfile.poller` → `python3 -m poller.main`). Async scheduler
(`src/poller/main.py`) with a 10 s tick that runs: (a) the REST fetchers on
their intervals with push-failover deference, (b) a small set of in-process
sub-minute/15-min skills as subprocesses (tfr-enrichment, route-impact,
cps-recompute, train/flight-impact, osint-monitor, cleanup/prune jobs), (c) the
trigger reactor for admin-issued manual refreshes, and (d) the watchlist sweeps
(expiry, flight/train/vessel checks, local-aircraft cross-reference, weekly FAA
and OpenSky registry downloads). Also hosts `WatchlistFileWatcher`, which loads
the permanent watchlist files in `/opt/corporatetraveldc/watchlists/`
(`permanent_flights.json`, `permanent_trains.json`, `permanent_vessels.json`,
`permanent_drones.json`). Always-on. The poller *image* is also reused as the
execution environment for every timer-fired skill container.

**ingest** (`Containerfile.ingest` → `python3 -m ingest.main`). The push-ingest
supervisor (§3). Deployed as **seven containers sharing one image**:
`corporatetraveldc-ingest-core` (NWWS-OI + Amtrak + local airspace monitor,
zero SWIM feeds) plus six single-feed containers (`-ingest-fdps`, `-ingest-stdds`,
`-ingest-tfms`, `-ingest-notam`, `-ingest-tbfm`, `-ingest-itws`), each setting
`SWIM_NMS_SKIP_FEEDS` to the five feeds it does not own and
`LOCAL_AIRSPACE_ENABLED=false`. Writes flight/surface/weather/NOTAM/TMI tables
and stamps `push:<feed>` heartbeats into `feed_state`. Always-on.

**pusher** (`Containerfile.pusher` → `python3 -m pusher.main`). A 30 s loop
(`src/pusher/main.py`) that reads what poller/ingest wrote and fires alerts:
`push_vip_tfrs()` (unnotified VIP TFRs → ntfy p5 + Pushover Emergency via
`hot_push()`), `push_cps_update()` (CPS score/label changes), `push_wx_change()`
(wind speed/direction deltas, freshness-gated), `push_flight_watchlist_landings()`
(landing detection for watchlist sessions — explicitly owned here, not by
local_airspace), and `push_watchlist_retries()`. Always-on.

**runner** (`Containerfile.runner` → `uvicorn main:app`, port 8001; a second
instance `corporatetraveldc-runner-demo` runs on port 8005 with `DEMO_MODE=true`).
The internal PWA backend (§6). Notably it holds **no shared-DB connection for
operational data** — it proxies the web API server-side (injecting the cert-tier
`RUNNER_ENRICHED_TOKEN` so the browser never sees it); its only direct sqlite3
use is its own chat-history DB (`CHAT_DB_PATH`). Always-on.

**demo** (`Containerfile.demo` → `python3 -m demo.recorder`) — the archive
recorder polling the live API every 5 min into `/var/lib/corporatetraveldc/demo.db`
(zlib-compressed, deduped, 364-day rolling retention). **demo-api**
(`corporatetraveldc-demo-api.container` → `uvicorn demo.demo_api:app`, port
8004) — the read-only public playback API over the *sovereign* scrubbed DB (§9).
Both always-on.

**amtrak-tracker** (`Containerfile.amtrak-tracker` → `python3 -m
amtrak_tracker.main`, port 8898 per `config.amtrak_local_url()`). Push-primary
Amtrak status for WAS: polls amtraker.com, writes `amtrak_status`, stamps
`push:amtrak` so the poller's amtrak fetcher stays quiet. Always-on. (Note:
`src/ingest/amtrak.py` is a *second*, in-ingest Amtrak poller with the same
heartbeat pattern — see §11.)

**acars-watcher** (`src/acars_watcher/acars_watcher.py`, its own quadlet).
Triple-source ACARS/VDL2 watcher: local UDP from acarsdec/dumpvdl2, airframes.io
REST, ACARS Drama Jumpseat REST; classifies emergency/divert/EDCT signals from
message text and fires ntfy via the dispatch admin API; syncs its registration
watchlist from the dispatch OOOI watchlist. **ais-watcher** and **utm-watcher**
(`src/ais_watcher/`, `src/utm_watcher/`) follow the same standalone-watcher
pattern for AIS vessels and OpenDroneID/Remote-ID drones respectively — both
quadlets are currently `.disabled` (no receiver hardware yet); utm_watcher's
UDP parser is explicitly defensive/best-effort pending real captures and its
USS REST poller is an honest inert stub.

**Supporting third-party containers** (quadlets, not this repo's code): the
SDR/feed stack (ultrafeeder, piaware, fr24feed, planefinder, airnavradar,
acarshub, acarsrouter, dumpvdl2), ntfy (port 2586), Nextcloud (app+db, behind
nginx on 127.0.0.1:8090), openwebui, rss-bridge, protonbridge (mail relay),
csexec-contact. The llama.cpp servers are **host-level systemd services**, not
containers (`corporatetraveldc-llama-hot/chat/report-N.service` — see §5).

Dependency sketch: ingest + poller/fetchers write the DB → pusher and web read
it; skills read the DB + RSS and write the vault (WebDAV) + ntfy; runner reads
web (HTTP) + local receivers; demo recorder reads web; demo-api reads only the
scrubbed sovereign DB; watchers call web's admin API.

## 3. Data ingest layer (`src/ingest/`)

### 3.1 Supervisor and configuration

`ingest/main.py` is an asyncio supervisor: it applies its curated subset of DB
migrations (v1–v7, v13–v15, v18–v20, v28–v30, v34, v36, v37, v40, plus
`db_swim.init_db_swim_v41/v42/v44/v45/v46` — deliberately not `init_db_all()`),
then starts each enabled source under `_supervise()` (restart-on-crash with a
10 s backstop delay): the SWIM NMS client, NWWS-OI, and the in-ingest Amtrak
poller, plus the `LocalAirspaceMonitor` daemon thread when
`LOCAL_AIRSPACE_ENABLED` (only ingest-core sets it true). `ingest/config.py` is
entirely env-driven from `/etc/corporatetraveldc/dispatch.env` +
`dispatch-secrets.env`; each SWIM feed gets `SWIM_NMS_{HOST,VPN,USER,PASS,QUEUE}_<FEED>`
credentials, and missing credentials log `pending_credentials` and idle rather
than crash. The legacy AMQP client (`ingest/swim.py`) was removed 2026-07-19;
Solace NMS is the only SWIM transport.

### 3.2 SWIM client (`ingest/swim_client.py`)

One `_NmsFeedSession` per feed, each a daemon thread running
connect → receive-loop → reconnect (backoff ladder 15/30/60/60/60 s). Key
verified behaviors:

- **TLS is really validated** (2026-08-25 fix): certificate validation against
  the container trust store with an explicit
  `solace.messaging.tls.trust-store-path` (the native solclient does not share
  Python's default path resolution — the 2026-08-26 follow-up fix).
  Keep-alive widened to 5000 ms × 8 (≈40 s tolerance) to ride out the box's
  WiFi congestion bursts.
- **Client-side acknowledgement** on all six feeds (`_CLIENT_ACK_FEEDS`,
  default "all") — works around an SDK-internal auto-ack use-after-free
  (`Bad msg_p pointer`) that was crash-looping the stdds/tfms containers.
  A bad-message forensic capture hook writes structured records to
  `/var/lib/corporatetraveldc/swim_bad_message_captures/` (capped at 200).
- **Backlog fast-forward triage**: on reconnect after a long outage, if the
  first queued message is older than `SWIM_BACKLOG_STALE_SECONDS` (2 h), only
  messages under that age or in the newest 10% of the backlog span are offered
  to the parser; the rest are dropped unparsed.
- **Bandwidth-priority backpressure** (`_bandwidth_priority_says_pause`, read
  from the `bandwidth_priority_state` singleton row on a 5 s cadence, never
  per-message): `priority=weather` (auto-set by `poller/fetchers/nws.py` on
  Severe/Extreme DC alerts, or operator-set via `/admin/bandwidth-priority`)
  pauses the low tier (stdds, tbfm, itws, fns) while fdps+tfms keep full
  throughput; `priority=nexrad` pauses fdps only. Pausing means *not draining
  the queue* — the session stays connected (a mid-loop disconnect was found to
  hang the Solace SDK permanently). The former `priority=ollama` mode was
  removed 2026-08-28 post-llama.cpp-cutover.
- **Heartbeats**: `failover.mark_push_healthy(feed)` every 30 s while
  connected, via a 2-worker DB thread pool; per-message byte/record counters
  are accumulated in memory and flushed to `feed_data_usage` every 5 s
  (`_flush_feed_counters_once`) instead of per-message writes.
- The skip-feeds path (`SWIM_NMS_SKIP_FEEDS`) is log-only — a 2026-08-23 fix
  stopped skipped feeds from clobbering the owning container's shared
  `feed_state` row.

Message flow: Solace queue → `receive_message()` → per-feed handler
(`_handle_fdps_message` etc., lazy-importing the parser) → parser returns
normalized dicts → write functions in the parser module → `common/db.py` /
`common/db_swim.py` tables → (for alert-worthy events) `shared/watchlist.py`
or `shared/sector_coalesce.py` push paths.

### 3.3 Push/pull failover (`ingest/failover.py`)

The coordination contract between push and poll. Push sources stamp
`feed_state` rows named `push:<feed>` (`PUSH_FEEDS = fdps, stdds, fns, tbfm,
tfms, itws, nws`; amtrak uses the same mechanism from `amtrak_tracker` and
`ingest/amtrak.py`). The poller calls `push_is_healthy(feed, max_age=90s)`
before a fetch and skips its REST call if the heartbeat is fresh and
error-free. The heartbeat reflects *connection* health, not data arrival —
quiet SWIM periods do not trip fallback. `mark_push_down()` deliberately does
not bump `fetched_at`; aging out is what re-enables polling. Fails safe toward
polling. Note the FETCH_SCHEDULE history in `poller/main.py`: `tfr` and `nas`
had bogus `push_feed` mappings (stdds/tfms) removed 2026-07-23 after they
silently suppressed real REST polls for days — only `nws` and `notam`
(`push:fns`) still declare push twins in the schedule.

### 3.4 SWIM parsers (`src/ingest/parsers/`)

All parsers share a pattern: schemas were originally guessed, then corrected
against **real captured samples** (debug-capture dirs under
`/var/lib/corporatetraveldc/*_debug*`, capped per root tag); each file's
docstring carries the verified real schema. `geo_filter.py` provides the shared
relevance filter: within 250 NM of DCA, or airport in a 30-airport
`CORE_AIRPORTS` set, or NWS WFO in `CORE_WFOS`.

- **`fdps_parser.py`** (FDPS / SFDPS, FIXM XML, ~1,980 lines). The live feed is
  FIXM **3.0** (`MessageCollection > message > flight`); the original FIXM 4.2
  parser is kept as `_parse_fdps_message_fixm42_legacy` behind a namespace
  sniff. Handles source codes FH (flight plan), TH (track), CL (cancellation),
  HP/OH (handoff), HZ (heartbeat), plus AH/BA/LH/HX (allowlisted, generic
  extraction). Since 2026-08-30 the batch-aware `parse_fdps_messages()` is used
  (real documents batch up to 100 flights; previously everything past
  message[0] was dropped). Writes `flight_events` (plus squawk/registration/
  controlling_facility extras via `db_swim.update_flight_event_extras`),
  same-GUFI destination changes to `fdps_destination_changes`, route versions +
  genuine-reroute classification to `fdps_route_versions`
  (`_classify_route_change`, `_record_route_version`), diversion→continuation
  pairs to `fdps_diversion_continuations` (`_check_diversion_continuation`,
  with `_operator_class` gating GA/fractional to store-only), and alternate-
  saturation analysis (`_check_alternate_saturation`). Alerting:
  `check_marine_one()` (POTUS/Marine One callsigns within 50 NM of DCA →
  `swim_alert` + ntfy), `check_fdps_watchlist()` + approach/meter-fix proximity
  alerts (deduped via `PushDedup("fdps_prox")`).
- **`tfms_parser.py`** (TFMS, ~3,200 lines — the largest). Real structure is
  `tfmDataService > fiOutput > fiMessage[@msgType]`. Confirmed-live msgTypes
  with dedicated handlers: `TMI_FLIGHT_LIST` (per-flight TMI/FCA assignment),
  `FlightModify`/flight-plan amendment, `trackInformation`,
  `flightPlanInformation`, `RESTRICTION`, `GDP` (`fi:gdpCompression`), `GS`
  (`fi:gsAdvisory`), `AFP` (`fi:afpAdvisory`/`afpCancel`), `APTC`
  (`fi:airportConfigMessage` — runway config + rates), `GADV`
  (`fi:generalAdvisory` ATCSCC bulletins), `FXA` (`fi:feaFca` FCA polygon
  definitions), `TMI_UPDATE` (reroute amendment status), `FADT` (EDCT slot
  lists → `tfms_edct_slots`), `PARAM` (delay stats →
  `tfms_param_delay_stats`), `REROUTE` (advisories → `tfms_reroutes`, with
  watchlist hits), flight-times (`_handle_flight_times` — airline-reported
  OOOI via `flightTimeData`), departure/arrival information, flight-route
  (diversion-indicator classification), and flight-plan cancellation
  (`_handle_flight_plan_cancellation` → `tfms_plan_removals` with trigger
  classification). Programs land in `nas_programs`; TMI watchlist matches fire
  through `watchlist_event_hit`; escalation flows through
  `sector_coalesce.fire_family_alert(family="tfms")`.
- **`smes_parser.py`** (STDDS queue). Parses `asdexMsg` SMES/ASDE-X surface
  tracks (→ `surface_tracks`, `check_surface_alerts`), TAIS
  `TATrackAndFlightPlan` terminal tracks (→ `terminal_tracks`,
  `check_stdds_alerts`), `SafetyLogicHoldBar` runway safety-logic status (→
  `stdds_safety_status` + history, `check_incursion_alert`),
  `SurfaceMovementEventMessage` taxi/spot events (→ `surface_movement_events`,
  `check_taxi_alerts`, and `check_smes_watchlist_oooi()` — ASDE-X-observed
  OOOI, often minutes ahead of TFMS). Since 2026-08-30 also the four TDES/APDS
  shapes on the same queue: `RVRDataUpdateMessage` (per-runway RVR →
  `stdds_rvr`), `TowerDepartureEventMessage` (gate + clearance time →
  `tdes_departure_events`), `TDLSCSPMessage` (PDC/CPDLC text →
  `tdls_messages`, with regex-extracted EDCT/route in v42 columns), and
  `DATISData` (→ `datis_snapshots`). Deliberately unparsed: Asset*/
  *ServiceStatus heartbeats.
- **`tbfm_parser.py`** (TBFM metering). Real schema is
  `env[@envSrce="TMA.{ARTCC}.FAA.GOV"] > tma > air[@apt,@dap,@aid,@gufi]` with
  `<eta><mfx>/<eta_mfx>/<eta_rwy>...` metering updates (`<flt>`-only elements
  are plan updates, skipped). Writes `tbfm_sequences`; feeds the watchlist TBFM
  status columns and `sector_coalesce` (family "tbfm").
- **`itws_parser.py`** (ITWS). Real schema is flat `<itws_msg>` routed by
  `product_msg_name` — 25+ confirmed products. Simple alert-style products are
  parsed (Microburst ATIS, Wind Shear ATIS, Tornado Alert/Detections, Terminal
  Weather Text, etc. → `itws_alerts`, severity 1–6, `check_itws_alerts` with
  severe-weather periodic heartbeat pushes); heavy raster products
  (Precipitation Long Range 920×920 RLE grids, etc.) are documented as
  known-unparsed. Airport codes normalized to K-prefixed ICAO.
- **`aim_parser.py`** (AIM/FNS NOTAMs, AIXM 5.1 `AIXMBasicMessage`). Storage/
  alert routing: DC permanent set (KDCA/KIAD/KBWI/KFDK/KHEF/KJYO/KGAI) always;
  transient set from today's runsheet airports; DC-region ARTCCs
  (ZDC/ZNY/ZID/ZTL/ZOB) always stored; FDC NOTAMs elsewhere only if nationally
  significant (`_is_national_significant`: CFR 91.137/141/143/145, 99.7, VIP/
  airshow/closure keywords); VIP (POTUS/VP/AF1/AF2/Marine One) always stored +
  alerted → `hot-alerts` p5. Flight-restriction NOTAMs → `fdps-alerts`/zone
  topics p4 first-occurrence (not escalation-gated); the rest → `nas-alerts` p3
  + escalation-gated `aim_fns-*` topics. Dedup is forward-only on notam_id with
  a full content hash (2026-09-03 redesign).

### 3.5 NWWS-OI (`ingest/nwws.py`)

XMPP (slixmpp-style) client joining the NWWS-OI MUC, filtering by WFO
(`NWWS_WFO_FILTER`, `geo_filter.is_core_wfo`), parsing VTEC phenomenon/
significance pairs through a ~40-entry `_VTEC_MAP` (Tornado Warning → Extreme/
Observed, etc.) into `db.upsert_nws_alert` — the push twin of the poller's
`nws` fetcher, heartbeat key `push:nws`.

### 3.6 Local airspace (`ingest/local_airspace.py`)

`LocalAirspaceMonitor` (thread, ingest-core only): polls ultrafeeder's
`/data/aircraft.json` every 15 s (receiver at `ULTRAFEEDER_LAT/LON`, 80 NM scan
radius) and drains the ACARS router TCP JSON-lines stream every 10 s. Writes
`local_aircraft`, `acars_messages`, `local_airspace_alerts`; alerts on watched-
aircraft proximity (30 NM), Marine One (50 NM), and emergency squawks
7700/7500/7600. Landing detection is explicitly *not* here (pusher owns it).

### 3.7 Amtrak (`ingest/amtrak.py` and `src/amtrak_tracker/`)

Both poll `api.amtraker.com/v3/trains` and write `db.insert_amtrak_status`
with the `push:amtrak` heartbeat so the poller's fetcher defers. The
amtrak_tracker container is the deployed push-primary (quadlet
`amtrak-tracker.container`); `ingest/amtrak.py` is the same capability inside
ingest-core, gated by `AMTRAK_ENABLED` (default true). Exactly one writer is
active at a time by the heartbeat contract, but two implementations exist
(§11).

## 4. Poller and skills layer (`src/poller/`)

### 4.1 Scheduler (`poller/main.py`)

Two in-process loop classes plus timers:

- `FetchLoop` — imports `poller.fetchers.<name>` and calls its module-level
  `run()` in an executor. `FETCH_SCHEDULE`: tfr (300 s), metar (300), nas
  (300), nws (300, push twin `nws`), notam (300, push twin `fns`), runsheet
  (300), atcscc_opsplan (3600), dca_fids (300), iad_fids (300), eurocontrol
  (900), jasdat (900). `active_interval`/`active_check` let a fetcher speed up
  while a matching watchlist session is live.
- `SkillLoop` — runs a skill script as a subprocess (own SR-1/SR-2 state) as a
  background task with an in-flight guard. `SKILL_SCHEDULE`: tfr-enrichment
  (300 s), route-impact (300), cps-recompute (3600), train-impact (900/300
  active), flight-impact (900/300 active), osint-monitor (900), flight-cleanup
  (daily), audit-log-prune (daily), retention-prune (daily). LLM skills get a
  2000 s subprocess timeout (`_OLLAMA_SKILL_TIMEOUT`).
- `TriggerReactor` — consumes JSON trigger files dropped by the web admin API
  (`refresh_feed`, `force_recompute_cps`, `force_opsplan_snapshot`,
  `force_osint_scrape`, `push_test_alert`) and resolves them in `trigger_log`.
- `WatchlistSweep` — expiry sweep (60 s), flight sweep (120 s; local ADS-B +
  FDPS cache + FIDS + schedule inference + the OOOI phase state machine),
  train sweep (300 s, amtraker), vessel sweep (300 s, AISHub/Kpler), local-
  aircraft cross-ref (60 s), FAA registry (daily) and OpenSky registry
  downloads via `_FAARegistrySweep`/`_OpenSkyRegistrySweep`.

The poller applies the widest migration subset (v1–v38 plus v43).

### 4.2 Fetcher pattern (`src/poller/fetchers/`, 17 files)

Each fetcher is a flat module with constants (URL, timeout, station lists), a
parse function, and `run()` that fetches, parses, upserts via `common/db.py`,
and stamps `db.upsert_feed(...)` with a payload hash for change detection.
Representative examples read in full: `metar.py` (aviationweather.gov ADDS,
7 DC stations, parses ceiling/vis/wind/precip for CPS), `nws.py`

### 4.3 The skill pattern (`src/poller/skills/`, 45 files)

A "skill" is a standalone script (one `main()`, run either by a systemd
timer-fired oneshot container executing
`scripts/verified-exec.sh python3 src/poller/skills/<x>.py`, or by the poller's
SkillLoop). The canonical shape, confirmed across representative reads
(`aviation_daily_watch.py` in full; ops_brief, ep_advance_brief, osint_monitor,
second_brain_daily and others in part):

1. **Gather** — DB queries, RSS via `_fetch_week_items`/`shared/rss_catalog`,
   retrieval ranking via `common/rss_retrieval.retrieve()` (lexical TF
   retrieve-then-cite, explicitly not embeddings), optional
   `common/entity_tracking.run_tracking_pass()` + `get_boost_terms()`.
2. **Synthesize** — `common.llm.generate(...)` against a dedicated
   `corporatetraveldc-pi5-<skill>:latest` persona name, with an explicit
   per-skill timeout and `allow_anthropic=False` on the newer skills; on
   `None`, a deterministic fallback (raw headlines / template text).
3. **Write** — state-dir caches (`config.state_dir()`), the second-brain vault
   via `second_brain.webdav_client.put()` + `index_note()`, everything passing
   `second_brain.scrub_gate.gate()` first; and/or ntfy via
   `common/ntfy_push`.
4. **Account** — `sr1_log.log_usage()` in a `finally` block, plus (newer
   skills) `ntfy_push.send_run_status()` health ping to `dispatch-ops`.
   SR-2 `check_gate()`/`commit_gate()` where inputs can repeat; time-bounded
   skills declare themselves SR-2-exempt in their docstrings.

**The 2026-09-02 split-call rearchitecture** (newest daily-watch pattern,
applied to aam/aviation and siblings): instead of one shared call instructed to
produce two framings ("ops" and "EP") back-to-back — which on quiet news days
collapsed into repetition loops that tripped `sanitize_llm_response()` and
discarded both framings (aam-daily-watch measured at ~83% fallback) — each
framing is now an **independent `llm_generate()` call** with a shared preamble
plus a per-flavor `FRAMING INSTRUCTION`, joined afterward; statuses become
ok/partial/fallback.

### 5.1 Database (`common/db.py`, 6,545 lines; `common/db_swim.py`, 1,294)

Single SQLite file (`/var/lib/corporatetraveldc/corporatetraveldc.db`), WAL
mode, `sqlite3.Row`, context-managed `conn()` (commit/rollback/close). The
schema is authoritative *in code*: a base `SCHEMA` plus additive numbered
blocks `SCHEMA_V2`…`SCHEMA_V40`, `SCHEMA_V43` in db.py, and
`SCHEMA_SWIM_V41/V42/V44/V45/V46/V47` in db_swim.py (v41+ were kept in a
separate module during the 2026-08-30 SWIM audit specifically so the diff
provably couldn't touch db.py's hardened OOOI/watchlist-identity logic; the
numbering continues across both files). All migrations are idempotent
(`CREATE TABLE IF NOT EXISTS`, duplicate-column-swallowing `ALTER TABLE`).
Every service applies a **hand-curated subset** of `init_db_vN()` calls at
startup; `init_db_all()` exists as the introspective run-everything variant
(used by tests) but deliberately does **not** pick up db_swim's versions —
callers needing those must call them explicitly (documented in db_swim's
docstring).

64 `CREATE TABLE` statements in db.py + 12 in db_swim.py ≈ 76 tables. Major
groups: feed health (`feed_state`, `feed_data_usage`, `pull_path_status`,
`bandwidth_priority_state`), aviation state (`tfrs`, `metar_snapshot`,
`nas_programs`, `notams`, `nws_alerts/forecast`, `wpc_discussions`,
`atcscc_opsplan`, `ops_plan`, `runsheet`, `international_aviation_feed`),
SWIM-derived (`flight_events`, `surface_tracks`, `terminal_tracks`,
`tbfm_sequences`, `itws_alerts`, `stdds_safety_status(+history)`,
`surface_movement_events`, `stdds_rvr`, `tdes_departure_events`,
`tdls_messages`, `datis_snapshots`, `tfms_edct_slots`,
`tfms_param_delay_stats`, `tfms_reroutes`, `tfms_plan_removals`,
`fdps_destination_changes`, `fdps_diversion_continuations`,
`fdps_route_versions`, `flight_ooooi_times`, `convective_sigmet_archive`),
watchlist (`watchlist_entries`, `watchlist_history`, `watchlist_sessions`,
`train_events`, `vessel_events`, `ustrains_departures`, `codeshare_map`),
registries (`faa_aircraft_registry`, `faa_aircraft_reference`,
`faa_ladd_aircraft`, `opensky_aircraft_registry`, + meta tables), decision

**OOOI authority machine** (db.py around SCHEMA_V40):
`_OOOI_SOURCE_PRIORITY = {fids:-1, adsb:0, tbfm:1, tfms:2, smes:3, acars:4}`
and `_OOOI_PHASE_ORDER = [pre_departure, out, off, on, in]`.
`update_watchlist_oooi_phase_authoritative()` always accepts a genuine
*forward* phase move from any source, never a regression; same-phase
re-confirmation is won by the higher-priority source. ACARS (aircraft's own
avionics) outranks SMES (independent FAA ground radar) outranks TFMS
(airline-reported times) outranks TBFM/ADS-B; FIDS ranks below everything
(known-unreliable timing, only accepted via the poller's ACARS
check-and-balance). Drones deliberately do *not* use this machine —
SCHEMA_V43 gives `watchlist_entries` separate `uas_phase` columns with a
free-alternating launched/landed vocabulary, because "OOOI only moves forward"
is semantically false for multi-sortie UAS.

### 5.2 LLM stack (`common/llm.py`, `common/personas.py`, `common/llama_pool.py`, `common/ollama_lock.py`)

**The naming is Ollama-vocabulary, the backend is not Ollama.** The 2026-08-27
cutover replaced Ollama with raw host-level `llama-server` (llama.cpp)
processes, but every public name (`OLLAMA_BASE_URL`, `ollama_model=`,
`ollama_post_with_retry()`, `OllamaBusyError`) was kept verbatim so zero call
sites changed. The 21 per-skill Ollama Modelfiles — each really the same
phi3:mini GGUF with a different SYSTEM block — were extracted verbatim into
`common/personas.py`: a `PERSONAS` registry (~23 entries) of
{tier, preamble (A: plain-text, B: markdown-allowed), task text, num_ctx,
num_predict, temperature, top_p}. `persona_key_for()` maps a
`corporatetraveldc-pi5-<suffix>` model string to its persona. Tiers:
**hot** = route-impact and tfr-enrichment (permanent port 8093,
`corporatetraveldc-llama-hot.service`, never queues), **chat** = the Dispatch
Drawer (permanent port 8094), **report** = everything else. Report routing
(2026-08-30): a persona whose `num_ctx` exceeds chat's 4096 goes to report-1
(port 8095, -c 8192), which is **on-demand** — started/stopped at the host
level by the consuming skills' quadlet `ExecStartPre`/`ExecStopPost` hooks
running `scripts/llama-report-ondemand.sh` (ep-advance, dispatch-desk-memo,
second-brain-weekly, ep-advance-venues) — everything else shares the chat
port. The original elastic report pool was abandoned pre-ship because a
containerized caller cannot spawn host processes; `llama_pool.claim_port()`'s
flock path remains but is currently unused. `ollama_lock.py` is gutted to just
the `OllamaBusyError` exception class (the hot/report mutex it implemented is
structurally obsolete with dedicated ports).

`common/llm.py` — the one funnel for all inference:

- `generate(system, prompt, ollama_model, max_tokens, temperature, priority,
  timeout, allow_anthropic)` → local llama.cpp first; returns `None` on any
  failure so callers use their deterministic fallback. Two independent gates
  control the Anthropic (claude-haiku-4-5) cloud fallback: per-call
  `allow_anthropic` and the global `ANTHROPIC_FALLBACK_ENABLED` env var —
  **default false (fail-closed) since 2026-08-26, and explicitly false in this
  box's dispatch.env**, so every caller on this deployment is
  local-or-deterministic.
- **Signed-manifest integrity gate**: `_verify_before_inference()` at the top
  of `ollama_post_with_retry()` verifies the calling skill's own source file
  (first stack frame outside llm.py) and, for a `corporatetraveldc-pi5-*`
  model, the corresponding `corporatetraveldc.<suffix>` Modelfile against the
  signed MANIFEST via `scripts/verify-manifest.sh`, once per process. Failure
  raises `IntegrityCheckFailed` — deliberately loud, not folded into the
  None-fallback contract.
- **Prompt sanitization** (`sanitize_prompt_text`): strips control chars,
  redacts shell/script-injection-shaped patterns (shebangs, backticks, `$()`,
  `<script`, `eval(`, `rm -rf`), truncates 300+-char unbroken tokens — applied
  centrally to every prompt, never to the trusted persona system text.
- **Response guard** (`sanitize_llm_response`): four live-specimen-derived
  checks — trailing-fragment trim on token-cap hits (`done_reason=length`),
  persona-echo cut (the model regurgitating its own SYSTEM block; keeps
  substantial content before the echo), long-line repetition loop (≥3 exact
  repeats of a >40-char line → discard whole response), short-line degenerate
  run (≥5 identical consecutive lines → trim), plus a narrow `'sWord` spacing
  repair. Each guard's docstring cites the real 2026-08-17 failure specimens
  it was validated against. A rejected-but-received response is logged
  distinctly from an availability failure (2026-09-02).
- **Pre-flight gates** for non-hot calls: a thermal cool-launch wait (hold up
  to 240 s for CPU ≤62 °C before adding inference heat) and a load gate (hold
  up to 180 s for load1 ≤7.0). Both bounded, both proceed anyway on timeout.
  Contention-attributable failures (busy slot, generation timeout — but
  deliberately *not* connect errors) are appended to
  `llm_load_fallback_events.jsonl` for `scripts/thermal-ingest-guard.py`'s
  shed decision.
- Large tracts of dead apparatus (governor-pause readiness waits, mid-flight
  retry params, ingest backpressure, cold-load preload) were **deleted
  outright** in the 2026-08-27→30 passes, each with a tombstone comment
  explaining why — the file's history-comment density is itself a repo
  convention.

### 5.3 Push dedup (`common/push_dedup.py` — redesigned 2026-09-03)

Shared JSON-file-backed dedup state (`state_dir()/pusher-<name>-dedup.json`)
used by SWIM parsers, the watchlist, pusher, and skills. As of the 2026-09-03
redesign (root cause: UAL1369 — three unchanged TFMS TMI assignments each
re-paged 7× in 42 min because TFMS rebroadcasts active TMIs every ~5–8 min and
the old "content changed OR window elapsed" semantics re-fired on the clock):

- `should_push(key, content_key, hot=)` is now **forward-only**: fires on first
  sighting or a genuine content-hash change; an unchanged hash stays
  suppressed indefinitely, up to the retention horizon
  (`max(dedup_secs*10, 7 days)`), past which one deliberate slow re-fire
  occurs. `hot=True` bypasses dedup entirely (VIP/POTUS p5).
- `should_push_periodic()` keeps the old OR semantics under an explicit name,
  reserved for genuinely time-based designs: TTL idempotency guards (the ntfy
  ambiguous-401/403 guard), constant-content episode gates (fdps proximity,
  flight landing), and deliberate still-active heartbeats (severe ITWS, feed
  health, active VIP TFR — pusher's hourly VIP re-push is intentionally on
  this API).
- Cross-process correctness (2026-08-16 fix): mtime-aware reloads plus
  flock-guarded read-merge-write with atomic replace, since ingest containers
  and the poller share the same state files. Each write also evicts entries
  older than retention (2026-08-26 unbounded-growth fix).
- Helpers: `content_hash()` (12-char MD5) and `bucket_count()` (band a churny
  integer so ±1 jitter hashes identically).

### 5.4 Watchlist (`shared/watchlist.py`)

The shared flight/train/vessel/drone watchlist engine used by ingest, poller,
pusher and web. `EntryType = flight | train | vessel | drone`. Key elements:

- `watchlist_event_hit(entry_id, summary, detail, priority)` — the single
  event funnel: forward-only dedup via `_check_dedup` (payload-content hash
  with ISO timestamps bucketed to 10 min and per-trigger continuous-telemetry
  keys excluded from the hash — position churn must not defeat suppression,
  while `vessel_position` keeps lat/lon in-hash on purpose), then a dual ntfy
  fire (domain topic `flight-alerts`/`train-alerts`/`vessel-alerts` + concise
  `dispatch`), then `watchlist_history` + last-event bookkeeping. Titles are
  newline-collapsed *before* truncation (a real silent-loss incident).
- `resolve_flight_identity()` — **local-only** identity resolution (operator
  directive 2026-08-27): the box's own ADS-B `aircraft.json`, then
  already-ingested FDPS, then local FAA/OpenSky registry tables; hex-locks the
  entry on first live contact (`db.set_watchlist_identity`) and fires exactly
  one identity-resolved notification. Handles the "AA5265 is also a valid hex
  string" ambiguity and the `_resolved_via_hex` tautology guard. Called from
  both the poller sweep and the TFMS OUT-transition handler ("the second the
  OUT gets pushed, it forces a resolve").
- Sweeps: `sweep_expired_transient`, `sweep_landed_flights`,
  `sweep_landed_trains` (with `_amtraker_still_live` cross-check),
  `extend_auto_remove_for_delay`.
- `_fire_ntfy_dual` has its own retry ladder + the 401/403
  ambiguous-status idempotency guard (never claims success, never resends
  within 90 s — see the 2026-08-25 correction note).
- `WatchlistFileWatcher` — syncs the permanent JSON watchlists from
  `/opt/corporatetraveldc/watchlists/` into the DB.

### 5.5 Sector coalescing (`shared/sector_coalesce.py`)

ARTCC-sector/corridor alert coalescing and escalation. Static maps:
`_SECTOR_FACILITY_MAP` (DC_LOCAL, NEW_YORK, BOSTON, ST_LOUIS, ATLANTA, plus
OCEANIC_ATLANTIC/GULF left with deliberately empty facility sets pending real
captures) and `_ARTCC_GROUPS` (8 zones: zny, zdc, zid, zob, zatl→ZTL, zhu,

Escalation is a two-window comparison (15-min rolling window ≥3× the prior
window, floor 3) → priority+1 and an `[ESCALATING/SECTOR]` tag. Per-topic
throttle/enable/sanitize overrides and per-sector/per-feed silence toggles are
JSON-persisted. Entry points: `maybe_fire_coalesced_alert()` and
`fire_family_alert(family=...)`, which fires the aggregate `<family>-alerts`
topic (escalation-gated by default) and the per-zone `<family>-<zone>` topic
off one shared classification. Consumers: tbfm, tfms, itws, aim_fns, fdps
NOTAM restrictions.

### 5.6 ntfy push (`common/ntfy_push.py`) and Pushover (`common/pushover.py`)

`send()` is the central push: plain-text body, mandatory `title` (it becomes
the SMTP Subject for ntfy's email relay — the only client-side filter), per-
topic `Click:` deep links into the runner (`TOPIC_CLICK`, base =
`config.runner_click_base()`, defaulting to the Tailscale hostname since

`send_dual()` fires full + concise topics; `send_run_status()` is the

Pushover Emergency (auto-retrying until acked) for priority-5 events via
pusher's `hot_push()`.

### 5.7 SR-1 / SR-2 governance (`common/sr1_log.py`, `common/sr2_gate.py`, `common/guardrails.py`)

- **SR-1** (`log_usage`) appends one CSV row per skill run to
  `/var/lib/corporatetraveldc/api-usage.csv`
  (timestamp, skill, model, input/output/cache tokens, status, gate_result),
  always in a `finally` block, never raises. **Real gap, verified across every
  call site in `src/poller/skills/`: every single caller passes `0, 0` for
  input/output tokens.** The log records *which* model path ran and the run
  outcome, but zero token accounting — the llama.cpp response's usage fields
  are never read back into it. `ctdc-token show-cost` therefore has no real
  token data to sum for local runs.
- **SR-2** (`check_gate`/`commit_gate`): SHA-256 hash of content-bearing
  inputs vs. the last committed hash in
  `/var/lib/corporatetraveldc/skill-state/<skill>.hash`; "skipped" means exit
  without an LLM call. The check and the commit were split 2026-08-25 so a
  crash mid-run leaves the gate open (the old combined write permanently
  suppressed retries on unchanged inputs). Skills with inherently time-bounded
  inputs declare SR-2 exemption in their docstrings instead.
- **`common/guardrails.py`** ports the SR1-mutation-confirmation and SR2
  model-tier-routing discipline from the retired agentic-tools MCP, logging to
  the same `audit_log`. Honest status: **zero callers anywhere in `src/`** —
  it is explicitly built ahead of need for a future frontier-model offload
  path (its own docstring says so).

### 6.2 Tiered auth (`src/auth/auth.py`, `src/ctdc_token/cli.py`)

Four tiers: T0 anonymous, T1 "cert", T2 "shares", admin. Elevation requires a
valid bearer token (`ctdc_<user>_<32 chars>`, SHA-256 hash stored, plaintext
shown once) **and** a non-public origin: nginx stamps `X-CTDI-Public: 1` on
the Cloudflare-tunnel public vhost, and `resolve_tier()` forces T0 before any
token lookup when that header is present — so even a valid admin token can
never elevate from the tunnel. This replaced an exploitable
X-Forwarded-For-prefix trust model (confirmed exploitable, then confirmed
closed — auth.py's docstring documents both). `require_admin(action)` is a
dependency factory that both authorizes *and* writes an `audit_log` row
(including denied attempts, with `_redact_audit_detail()` scrubbing secrets/
URLs from stored request bodies), so authz and audit cannot drift apart.
`resolve_identity()` adds user/department identity for the RSS visibility
model. `ctdc-token` (CLI) creates/lists/revokes tokens and has a `show-cost`
subcommand summarizing the SR-1 CSV. Per memory and the 2026-07-17 rollout,
tokens are minted on demand; `db.active_token_count()` exists for the web
layer to report.

### 6.3 The runner (`src/runner/main.py`, 2,876 lines + React frontend)

The internal PWA: FastAPI on 8001 serving a Vite/React 18 build
(`src/runner/frontend/`, react-router; components include MapView (Leaflet
ADS-B), TfrView, BriefView, TrainMapView, AisMapView, UtmMapView,
SignalsView, EventIntelView (OSINT), IntelView (RSS), NtfyFeedView,
StatusView, GraphView (knowledge graph), DispatchDrawer (chat), AdminView,
plus accessibility work — AriaCompassRegion, wake-lock, visibility-aware
polling). The backend is a server-side proxy/aggregator: it calls the web API
(injecting `RUNNER_ENRICHED_TOKEN` for Tier-1 endpoints so the browser never
holds a token), local receivers (ultrafeeder, acarshub, AIS-catcher), and
external ACARS/AIS fallbacks (acarsdrama Jumpseat → airframes.io; Kpler for
AIS) bounded to 250 NM of the receiver. `/api/ask` is the Dispatch Drawer
chat (local-data → Open WebUI proxy → llama.cpp chat port; history in its own
`CHAT_DB_PATH` sqlite file). `/api/stream` and `/api/ntfy/stream` provide
SSE. RSS endpoints wrap `shared/rss_catalog` with identity scoping. Retired
hostnames are hard-rejected (`_RETIRED_HOSTNAMES`). Demo mode: the
`runner-demo` quadlet instance (port 8005) sets `DEMO_MODE=true` +
`DEMO_SESSION_SECRET` and gates behind `demo.profiles` password sessions; the

## 7. Second brain (`src/second_brain/`)

The vault is a Nextcloud account ("corporatetraveldc") reached over WebDAV
(`webdav_client.py` — env-driven credentials, Host-header spoof for loopback,
no delete operation by design, and *no silent user fallback* after a real
wrong-account-write incident). Layout is PARA-style under the
`corporatetraveldc/` business root: `00-Inbox/` (rss, cross-link-findings),
`01-Sources/` (daily, manual, personal-notes, transport-patterns),
`03-Entities/` (wikilink hubs), `04-Syntheses/` (daily, weekly),
`archives/`.

- **Scrub gate** (`scrub_gate.py`): every ingestion path — automated skills,
  manual `remember`, RSS — calls `gate(text)` before any vault write. It is a
  **block** gate, not a redactor: CUI radio program names (SHARES/HEARS/HEART)
  co-occurring with frequency-shaped tokens, or SSN-shaped tokens, raise
  `ScrubGateBlocked`. Honestly scoped in its own docstring as a first-pass
  regex heuristic.
- **Capture** (`remember.py` + `web/routes/remember.py`): one shared code path
  (scrub gate → WebDAV put → index) for CLI and REST; explicit
  `author_kind` human/agent provenance tagging (2026-08-24 fix — agent notes
  were being misclassified as human-authored); `dest_subdir` routing so
  personal-data findings land in `01-Sources/personal-notes/`.
- **Index** (`index_db.py`): a separate SQLite DB
  (`second_brain_index.db` — `vault_documents`, `vault_notes_fts` FTS,
  `vault_links`) rebuilt/updated over WebDAV; deliberately not part of
  `common/db.py`. CLI: `--scan`, `--summary`. `scripts/second-brain-search.sh`
  is the operator/agent query wrapper.
- **Semantic layer** (`semantic/` — **real code, not a stub**: model.py 579
  lines, compile.py 888, export.py 308, plus `__main__`). `model.py` unifies
  the four divergent vocabularies (rss_catalog keys, knowledge-graph lexicon,
  index folder categories, entity-ingest categories) plus free-text tags into
  one governed ontology (`ontology.json`); `compile.py` materializes it into
  `semantic_*` tables inside the vault index (full DROP/CREATE each run,
  deterministic rule-based note→concept assignment with recorded
  rule+evidence, unmapped tags surfaced as a governance backlog); `export.py`
  renders JSON, SKOS/Turtle, and a token-budgeted LLM "context pack" to the
  shared data volume. Run daily by `semantic_compile_daily` (03:47 ET). The
  memory note that the semantic layer is "pending build" is out of date — it
  is built and scheduled; what remains open is the *mandatory-read-by-agents*
  policy around it.
- **Knowledge graph** (`knowledge_graph/` — also real): `lexicon.py` (curated
  entity regex lexicon + subtypes), `retrofit_links.py` (conservatively
  retrofits `[[wikilinks]]` — entity hub notes in 03-Entities/ + marked
  per-note footers — the only writer), `build_graph.py` (read-only builder:
  nodes = notes, edges = actual wikilinks with organic/retrofit origin,
  emitting a standalone HTML viz served at `/api/v1/knowledge-graph/html`).
- **Documents** (`doc_generation.py`): markdown → .docx/.pptx/PDF via
  python-docx/python-pptx + LibreOffice headless; minimal parser, honestly
  scoped. `client_entity_ingest.py`: vCard 2.1 exports → a deduplicated
  `entities` table in the index DB (no live CRM pulls yet — those are the

## 10. Cross-cutting conventions worth documenting

These recur across many files — the repetition is the signal:

1. **Signed-manifest integrity.** `scripts/sign-manifest.sh` (human-run, GPG;
   `--agent` mode uses a separate no-passphrase agent key gated on a
   session-grant or a live ntfy Allow/Deny approval, and every agent
   signature is audited) produces `MANIFEST.sha256` + `.asc`.
   `scripts/verify-manifest.sh` checks the whole tree or scoped targets.
   Enforcement points: `scripts/verified-exec.sh` prepended to **every skill
   container's Exec=** (scoped to what the image actually bakes in);
   `common/llm.py` verifying the calling skill file + Modelfile before any
   inference; `push-public.sh` refusing to push on verification failure.
   Consequence for contributors: **editing any covered file without
   re-signing breaks skill startup and LLM calls** by design.
2. **Public-mirror scrub.** `scripts/push-public.sh` force-pushes to public
   mirrors only after `scripts/scrub-public-tree.py` rewrites the git tree:
   substitutions + regex sweeps, DROP_FILES, allowlist-based output
   verification, and — after a real credential-in-prose incident — a
   read-the-actual-secrets-file check that hard-fails if any live secret
   *value* from `dispatch-secrets.env` appears anywhere in the output tree.
3. **SR-1/SR-2 discipline** (§5.7): `log_usage()` in `finally` in every skill;
   `check_gate`/`commit_gate` (commit only after the guarded work succeeded)
   or an explicit documented exemption.
4. **Secrets** live only in `/etc/corporatetraveldc/dispatch-secrets.env`
   (0600; template `dispatch-secrets.env.template`; populated by
   `scripts/populate-secrets.sh`) and non-secret config in `dispatch.env`.
   `config.py` loads both at import; `require()` fails fast. No secret is
   hardcoded anywhere in `src/` (verified in the modules read; the scrub
   script's secrets-value check enforces it outbound).
5. **Deterministic fallback contract.** Every LLM caller treats `None` as
   "use my own deterministic output"; content-guard rejections are logged
   distinctly but honor the same contract. Cloud egress is fail-closed.
6. **Push failover / heartbeat contract** (§3.3): any feed with both a push
   and poll path uses `push:<feed>` heartbeats; poll defers at 90 s freshness.
7. **Forward-only dedup** (§5.3) with `should_push_periodic` reserved for
   genuinely periodic designs — new alert paths should default to
   `should_push`.
8. **Local-only position/identity resolution** (2026-08-27 hard rule):
   no third-party position/lookup APIs; local ADS-B → local FDPS → local
   registry tables; click-through globe.airplanes.live URLs are allowed as
   phone conveniences. (Documented exceptions: ACARS aggregators for message
   truth per `common/acars.py`'s operator directive, and the two rough-edge
   remnants in §11.)
- **OOOI confirmation authority** (memory + code agree): SWIM + network ACARS
   aggregators, never gated on the local receiver; the source-priority machine
   in db.py encodes it.
9. **Incident-comment convention.** Nontrivial fixes carry dated,
   root-cause-first comments citing the live incident/specimen (UAL1369,
   DAL926, brief_archive 1597…), and removed apparatus gets tombstone
   comments. The living docs should treat these in-code histories as the
   primary record.
10. **Debug-capture-then-parse.** Every SWIM parser was corrected against
    real captured messages; capture hooks are capped and keyed by root tag.
    New feed work should follow the same capture-first pattern.
11. **Quadlet resource discipline.** Every production container:
    `production.slice`, equal `Memory=`/`--memory-swap=`, `MemoryLow=`,
    per-skill `TimeoutStartSec` derived from measured budgets, and
    `verified-exec.sh` wrappers. Ops scripts (`scripts/*.sh`) cover watchdogs
    (feed silence, ADS-B link, SDR crashloop, container memory, thermal
    ingest guard, swim session health), maintenance windows, and scheduled
    restarts (`scheduled-ingest-restart`, `scheduled-llama-restart`).
12. **Time discipline** (operator rules, enforced in reviews rather than
    code): user-facing timestamps in America/New_York; check the box clock
    before time-of-day claims.
