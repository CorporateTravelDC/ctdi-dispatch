# scripts/agent-segmentation/secrets-allowlist-agent.txt  (profile: agent)
#
# Variable NAMES (never values) that AGENT accounts (group ctdc-agents) may read.
# secrets-subset.py copies exactly these, verbatim, from
# /etc/corporatetraveldc/dispatch.env + dispatch-secrets.env into
# /etc/ctdc-agent/agent-secrets.env (root:ctdc-agents 0640). Everything not
# listed here stays operator/container-only. See docs/AGENT_SEGMENTATION.md
# "Part 2 -- Secrets: what agents actually need".
#
# Format: one NAME per line; `#` comments; blank lines ignored. A name may be
# suffixed with `?` to mark it optional (--check reports it as "optional,
# absent" instead of "MISSING"). Derived 2026-10-03 by grepping the paths an
# agent actually runs (src/second_brain, .claude/skills/*/scripts,
# scripts/*.sh --status modes); each line says who consumes it.

# --- dispatch API -----------------------------------------------------------
# REMOVED 2026-10-04 (duel X1): DISPATCH_ADMIN_TOKEN. It reaches every
# require_admin route, including creating/reading approval requests for the
# operator's sudo / sign-manifest gate. An agent that needs a Tier-1 read gets
# a personal auth_tokens row from the operator, never the shared admin token.

# --- ntfy ---------------------------------------------------------------------
# REMOVED 2026-10-04 (duel X1): NTFY_TOKEN. Both ntfy users on this box
# (corporatetraveldc, dispatch) are role=admin with read-write on ALL topics,
# so the shared token let a team account READ the operator's approval-gate
# pushes -- and with them the Allow links. A team account gets its own ntfy
# user, write-only to the topics it needs, minted by the operator and stored
# as NTFY_AGENT_TOKEN in dispatch-secrets.env (optional until then).
NTFY_AGENT_TOKEN?

# --- service locations (non-secret facts from dispatch.env) ------------------
# The pamphlet's "current namespaces" section points agents at the local model
# server; LLAMA_BASE_URL is its address (renamed 2026-10-05; OLLAMA_BASE_URL is
# the deprecated alias, kept optional until it is removed from dispatch.env).
# The dispatch API base is not an env var -- tooling defaults to the Tailscale
# address (save_dispatch_state.py DISPATCH_BASE default); the pamphlet states
# it literally instead.
LLAMA_BASE_URL?
OLLAMA_BASE_URL?

# --- second brain (vault) ----------------------------------------------------
# REMOVED 2026-10-04 (operator, duel follow-up): NEXTCLOUD_ADMIN_USER and
# NEXTCLOUD_APP_PASSWORD. They are raw WebDAV ADMIN over the whole vault --
# any agent could delete or overwrite other agents' research. Reads go
# through GET /api/v1/vault/research (signed); writes will go through a
# signed, create-only workspace contribution route (later unit). Until it
# exists, an agent hands the text to the operator.

# --- coordination board -----------------------------------------------------
# REMOVED 2026-10-04 (duel H4): BOARD_KEY. The master board key posts under
# any `from` name, which defeats per-account attribution; agents sign with
# their own key (scripts/board-sign.sh, docs/BOARD_SIGNING.md). Answers the
# design doc's open question: no, agents do not get the board key.
