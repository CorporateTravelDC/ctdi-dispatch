# GTFS-Realtime protobuf decoding for the MARC + VRE train providers
# (2026-09-23, docs/TRAIN_PARITY_DESIGN_2026-09-23.md sec5). Closes parity
# break 5: MARC (88 entries) and VRE (32) are 39% of the train watchlist and
# had NO data source -- amtraker is Amtrak-only, and their train numbers
# COLLIDE with Amtrak's, so querying it for them returned a different
# railroad's train entirely (see the provider guard in poller/main.py).
#
# Both operators publish open, UNAUTHENTICATED GTFS-RT. Verified reachable
# 2026-09-23:
#   MARC static  https://feeds.mta.maryland.gov/gtfs/marc            193 KB
#   MARC tu/vp   https://mdotmta-gtfs-rt.s3.amazonaws.com/MARC+RT/   v2.0 pb
#   VRE  static  https://gtfs.vre.org/containercdngtfsupload/google_transit.zip
#   VRE  tu/vp   https://gtfs.vre.org/containercdngtfsupload/TripUpdateFeed
#                https://gtfs.vre.org/containercdngtfsupload/VehiclePositionFeed
# Both refresh ~30s. No API key for either.
#
# gtfs-realtime-bindings is the reference Python binding from MobilityData
# (the GTFS spec stewards) and pulls protobuf itself, so this is the only
# line needed.
#
# SCOPE NOTE: every image built from this file gets it (poller, ingest, web,
# pusher, demo, amtrak-tracker), because Containerfile.poller copies only
# this root requirements.txt -- there is no per-poller requirements file.
# Only the poller's train fetchers will import it. ~2 MB; accepted rather
# than restructuring the Containerfile layout for a single dependency.
gtfs-realtime-bindings>=1.0.0
